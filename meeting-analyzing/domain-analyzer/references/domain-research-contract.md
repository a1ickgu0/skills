# Domain Research Contract

## Corpus identity

The page corpus contains items identified by a profile-configured pattern. Each video analysis must link to exactly one source record in the configured Task 1 directory and preserve that identifier. The profile defines the item count, ID pattern, and directory structure.

## Research tracks

Assess each profile-configured track as applicable, not applicable, or unsupported by the video. Use the matching track files from the configured tracks directory as Task 1 context, not as substitutes for video evidence.

## Mandatory domain analysis extensions

In addition to the generic chronology and evidence ledger, include the extensions configured in the profile. These typically cover:

- technical and product mechanisms;
- platform and portfolio strategy;
- product/capability/availability matrix;
- demonstrations and their evidence boundaries;
- customer cases and quantitative-claim ledger;
- security and autonomy governance;
- operating, commercial, and competitive implications;
- explicit delta from the Task 1 page layer;
- unanswered questions.

## Task 1 delta statuses

For each material video contribution, classify it using the profile's delta vocabulary. Standard statuses:

- `confirmed`: supports the page-layer record;
- `expanded`: adds mechanism, detail, evidence, or scope;
- `contradicted`: conflicts with the page-layer record or another dated source;
- `newly-introduced`: absent from the page-layer record.

Record the Task 1 file and timestamp/source supporting the comparison.

## Evidence separation

Do not combine these categories in one undifferentiated claim:

- speaker statement;
- slide-only evidence;
- stage or recorded demo;
- customer claim;
- official cross-check;
- analyst inference.

Customer claims do not establish universal performance. Demo results do not establish production benchmarks.
