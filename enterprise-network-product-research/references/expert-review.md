# 未知推进与数通专家复核

## 先解释未知，再推进

“未披露”限定为已核查资料未披露，不声称厂商从未披露。“待核实”必须解释原因。先按影响（身份/筛选/推荐）、错误风险和可解决性排序，优先解决关键字段；不以空值最少为目标。

每个 research task 必须有 `id`、`claim_id`、`reason`、`priority`（`high` / `normal`）、`status`（`open` / `blocked` / `exhausted` / `resolved`）、`attempts`、`hypotheses`、`next_action`、`stop_reason`。attempt 包含 `action`、`source_ids`、`result`，访问失败也要记录，禁止编造已完成动作。hypotheses 为假设及验证条件的文字数组，不作为确认事实。

| 原因 | 推进路径 |
| --- | --- |
| `not_searched` | 检查对应 SKU 规格，再查字段相关的官方指南 |
| `applicability_unclear` | 检查 SKU、硬件修订、地区、软件和配置映射 |
| `conflicting` | 保存双方原文，核查日期、修订和适用条件；不自动选较新来源 |
| `configuration_dependent` | 明确线卡、电源、端口组等配置，必要时拆分 claim |
| `access_blocked` | 记录障碍，找官方替代载体，不绕过权限 |
| `not_found_in_checked_sources` | 列明已核查资料，评估继续查证价值 |

关键未知或未解决冲突，交付时至少有一次真实核查记录，或明确 blocked 原因；即使不继续也不能只写“待核”。open/blocked 必须有下一步；blocked/exhausted 必须有停止理由；resolved 必须有核查记录及对应更新后的 claim。exhausted 表示本次约定动作已完成，并非永远无法查明。

停止条件：已核查约定的来源类型、剩余动作收益低于任务预算，或存在无法解决的访问/用户决策障碍。记录影响和再启动条件。关键范围冲突仍等待用户决定；可默认偏好不阻塞独立研究。

## 专家知识先用于提问和异常发现

采集前根据设备形态列出预期检查项：接入口/上联/堆叠是否复用，模块是否标配，机框/线卡/网板限制，软件版本，PoE 电源与冗余模式。不能从同系列、连接器外形或产品定位直接继承具体参数。

采集后执行适用检查，并保留检查输入、公式、结果和限制：

- 容量：以已确认的可并发配置计算接口单向速率总和 S；仅当厂商定义为双向容量时与 2S 比较。差异是查证信号，不证明厂商错误；检查扩展模块、内部链路、阻塞比和统计口径。
- 包转发率：明确帧长、是否计入 FCS、前导码与 IFG 后再算。以含 FCS 的 64 字节以太帧、8 字节前导码/SFD、12 字节 IFG 为例，单向理论 pps = bit/s ÷ (84 × 8)；不把此口径直接套到未说明的官方 Mpps，也不把全双工自动乘二。
- PoE：区分 PSE 侧输出与 PD 侧可用功率、单口等级与整机预算；核查电源数量、冗余和降额。不以端口数乘等级上限认定整机可同时供电能力。
- 端口：核查速率模式、Combo、端口组和 breakout 并发限制，默认配置与最大配置分开。
- 身份：跨型号对比用于发现异常；认证、气流、硬件修订和交付差异未证实时不合并。

推导记录使用 input_claim_ids → rule/calculation → conditions → limitations，不能循环引用。输入未知或冲突时不能把输出写成官方确认。名称推测仅用于低风险候选或指导检索，不能据此推定 ASIC、低速兼容性或完整接口构成。

## 专家字段判定是必经步骤

对模板每一列按以下顺序处理，交付前逐项检查，不允许统一填“待核实（未逐项复核）”：

1. 直接事实：有适用官方值则采纳，保留版本/配置。
2. 领域推导：利用接口形态、明确速率集合、完整接口构成及配置进行归类、排除和计数。不存在对应接口可以推导0，无需每种速率都有官方否定句；不是“页面没写所以0”。
3. 条件结论：数量已确定而介质、软件或选配未确定时，保留确定数量，单列条件/冲突；不能把局部不确定扩散为整个字段未知。
4. 真正未知：接口清单不完整、名称省略上联/选配、兼容性缺证据、多个适用来源冲突时才建补证任务，明确究竟缺什么。

输入可以是完整产品名，但先检查名称是否省略可选模块、机框线卡、管理和堆叠。名称推导用 name_inferred，不能伪称官方直接；有官方完整接口清单则用 official_derived。两者均记录输入、规则、配置和边界。专家知识不能替代CPU/ASIC型号、发布时间或在售事实的查证。

| 输入 | 应得判断 | 禁止做法 |
| --- | --- | --- |
| 完整48GE+4个1/10/25/50G SFP56固定接口 | 40G/100G/200G/400G=0；固定2.5G/5G/10G电口=0；50G能力口4个 | 把未逐列查证当未知；或认为50G自动支持40G |
| 标配24GE，另有可选40G上联槽 | 标配40G=0，另注选配可达1；标配口数不包含未安装模块 | 写“设备不支持40G”，或把选配写成标配 |
| 只知“48口交换机” | 无法确定上联和端口种类，继续查 | 凭名字把所有未提速率填0 |
| SFP光口线卡完整业务清单，无电PSE口 | PoE口数=0（按电PSE定义的领域推导） | 将机框电源能力当作该线卡PoE预算 |
| 4个50G口，支持介质资料有差异 | 数量4；介质/版本单独待核 | 把确定的接口数量也清空 |
| R0X44C默认25g，另可配50g组 | 默认50G=0；指定全组50g最多24，写清是另一配置 | 将24直接当默认标配，或48+24相加 |

验收门禁：所有目标字段均已做“直接/推导/条件/未知”的判定；每个零值有明确配置及排除依据；每个未知说明为何领域知识不足以判断。不能用推导降低表面未知率，也不能因追求逐字原文而放弃合理推导。

## 更新与用户值

保留用户明确修正、历史证据与新候选值。新官方资料与用户值冲突时，不静默覆盖或忽略任何一方：当前值可保留为 user_asserted，新增 evidence、task 和 changes；user_resolution 记录待决或用户决定。已被替代的旧推导进入变化记录，不继续混在当前备注中。

衡量推进效果使用关键未知中已有核查记录的比例、推导可回放率、未解决冲突及其影响；分母和排除项必须公开。不设置未经校准的置信度百分数，不把未知减少率当唯一质量指标。
